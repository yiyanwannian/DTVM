# DTVM内存桶模式（Bucket Mode）详解

DTVM项目中的"内存桶模式"（Bucket Mode）是一种特殊的内存管理策略，用于高效管理WebAssembly线性内存。本文将详细解释内存桶模式的工作原理、实现方式和优势。

## 1. 内存桶模式概述

内存桶模式是DTVM中的一种内存分配策略，它通过预分配大块内存并将其划分为多个固定大小的"桶"（bucket），来高效管理WebAssembly实例的线性内存。这种模式主要用于支持内存保护和CPU异常检测，同时提高内存分配和释放的效率。

在DTVM中，内存桶模式对应的内存类型是`WM_MEMORY_DATA_TYPE_BUCKET_MMAP`，它是通过内存映射（mmap）实现的一种特殊内存类型。

## 2. 内存桶模式的实现

### 2.1 数据结构

内存桶模式的核心数据结构是`MmapBucketInstance`类，它表示一个内存桶实例：

```cpp
class MmapBucketInstance {
public:
  MmapBucketInstance(uint8_t *Addr, size_t BucketSize, size_t ItemSize,
                     size_t BucketMmapSize)
      : MmapAddr(Addr), Size(BucketSize), BucketItemSize(ItemSize),
        MmapSize(BucketMmapSize) {
    ItemsUsedSizes.fill(0);
  }
  
  // 内存桶的起始地址
  uint8_t *MmapAddr = nullptr;
  // 每个桶项的已使用大小
  std::array<size_t, WasmMemoryAllocatorBucketDuplicates> ItemsUsedSizes;
  // 下一个可用偏移量
  size_t NextOffset = 0;
  // 桶的总大小
  size_t Size = 0;
  // 每个桶项的大小
  size_t BucketItemSize = 0;
  // 映射的总大小
  size_t MmapSize = 0;
};
```

`WasmMemoryAllocator`类中与内存桶相关的成员变量：

```cpp
// 内存桶大小
size_t MmapBucketSize = 0;
// 每个桶项的大小
size_t MmapBucketItemSize = 0;
// 桶锁，用于线程安全
common::Mutex BucketLock;
// 活动桶映射：桶起始地址 => 桶实例
std::unordered_map<uint8_t *, std::shared_ptr<MmapBucketInstance>> ActiveBuckets;
// 最后创建的桶实例，WebAssembly内存实例将使用它
MmapBucketInstance *BucketInstanceForAllocate = nullptr;
```

内存桶模式在`WasmMemoryAllocator`构造函数中初始化：

```cpp
WasmMemoryAllocator::WasmMemoryAllocator(

      // ...

      MmapBucketItemSize = SingleInitFileSize;

  }
```

### 2.3 内存桶的分配

当需要分配WebAssembly线性内存时，`getOrCreateMmapSpace`方法会从内存桶中分配空间：

```cpp
WasmMemoryBucketSlice WasmMemoryAllocator::getOrCreateMmapSpace(
    const uint8_t *BucketAllocSand, size_t InitLinearMemorySize) {
  if (UseMmap) {
    common::LockGuard<common::Mutex> _(BucketLock);
    
    // 如果没有可用的桶实例，创建一个新的
    if (!BucketInstanceForAllocate) {
      // 通过内存映射分配大块内存
      size_t MmapSize = WasmMemoryAllocatorMmapSize;
      auto BucketMemAddr =
          (uint8_t *)::mmap(nullptr, MmapSize, PROT_NONE,
                            MAP_FILE | MAP_PRIVATE, MmapMemoryInitFd, 0);
      // ...
      
      // 创建新的桶实例
      ActiveBuckets.insert(std::make_pair(
          BucketMemAddr,
          std::make_shared<MmapBucketInstance>(
              BucketMemAddr,
              MmapMemoryBucketGrowMaxSize * WasmMemoryAllocatorBucketDuplicates,
              MmapMemoryBucketGrowMaxSize, MmapSize)));
      auto *NewBucketInstance = ActiveBuckets[BucketMemAddr].get();
      BucketInstanceForAllocate = NewBucketInstance;
      
      // 设置第一个桶项的使用大小
      NewBucketInstance->ItemsUsedSizes[0] = InitLinearMemorySize;
      NewBucketInstance->NextOffset += NewBucketInstance->BucketItemSize;
      
      // 返回桶切片
      return WasmMemoryBucketSlice{
          .Address = BucketMemAddr,
          .BucketBegin = BucketMemAddr,
          .BucketSize = NewBucketInstance->Size,
      };
    }
    
    // 使用最后一个桶实例分配
    auto Result = WasmMemoryBucketSlice{
        .Address = BucketInstanceForAllocate->MmapAddr +
                   BucketInstanceForAllocate->NextOffset,
        .BucketBegin = BucketInstanceForAllocate->MmapAddr,
        .BucketSize = BucketInstanceForAllocate->Size,
    };
    
    // 更新下一个可用偏移量
    BucketInstanceForAllocate->NextOffset +=
        BucketInstanceForAllocate->BucketItemSize;
    
    // 如果桶已满，将BucketInstanceForAllocate设为nullptr
    if (BucketInstanceForAllocate->NextOffset >=
        BucketInstanceForAllocate->Size) {
      BucketInstanceForAllocate = nullptr;
    }
    
    // 记录内存地址到桶地址的映射
    MemoryAddrToMmapAddr->insert(
        std::make_pair(Result.Address, Result.BucketBegin));
    
    return Result;
  }
  // ...
}
```

### 2.5 内存桶的释放

当不再需要WebAssembly线性内存时，`internalFreeWasmMemory`方法会释放内存：

```cpp
void WasmMemoryAllocator::internalFreeWasmMemory(const WasmMemoryData &Data) {
  // ...
  if (Data.Type == WM_MEMORY_DATA_TYPE_BUCKET_MMAP) {
    // 查找内存地址对应的桶地址
    auto MmapBucketIt = MemoryAddrToMmapAddr->find(Data.MemoryData);
    ZEN_ASSERT(MmapBucketIt != MemoryAddrToMmapAddr->end());
    auto *MmapBucket = MmapBucketIt->second;
    
    // 查找桶释放计数
    auto BucketFreedCountPtrIt = MmapBucketsFreedCount->find(MmapBucket);
    if (BucketFreedCountPtrIt != MmapBucketsFreedCount->end()) {
      // 增加桶释放计数
      auto *BucketFreedCountPtr = BucketFreedCountPtrIt->second;
      *BucketFreedCountPtr += 1;
      
      // 如果所有桶项都已释放，则解除映射
      if (*BucketFreedCountPtr >= WasmMemoryAllocatorBucketDuplicates) {
        size_t UnmapSize = MmapBucketSize;
        if (0 != ::munmap(MmapBucket, UnmapSize)) {
          ZEN_ABORT();
        }
        
        // 清理相关数据结构
        // ...
      }
    }
    
    // 从映射中移除
    MemoryAddrToMmapAddr->erase(MmapBucketIt);
  }
  // ...
}
```

### 2.6 内存桶的增长

当WebAssembly内存需要增长时，`enlargeWasmMemory`方法会处理内存增长：

```cpp
WasmMemoryData
WasmMemoryAllocator::enlargeWasmMemory(const WasmMemoryData &OldMemoryData,
                                       size_t NewMemorySize) {
  bool NeedFreeOldMmap = false;
  if (UseMmap) {
    // 检查是否使用内存桶
    bool OldUseMmap = (OldMemoryData.Type == WM_MEMORY_DATA_TYPE_BUCKET_MMAP ||
                       OldMemoryData.Type == WM_MEMORY_DATA_TYPE_SINGLE_MMAP);
    bool InstanceUseMmap =
        OldUseMmap && (NewMemorySize <= MmapMemoryBucketGrowMaxSize);
    
    if (OldUseMmap && InstanceUseMmap) {
      // 如果新大小仍在桶项的容量范围内，只需更新大小
      const auto &NewMemoryData = WasmMemoryData{
          .Type = OldMemoryData.Type,
          .MemoryData = OldMemoryData.MemoryData,
          .MemorySize = NewMemorySize,
          .NeedMprotect = false,
      };
      return NewMemoryData;
    }
    
    // 如果需要重新分配，标记需要释放旧内存映射
    NeedFreeOldMmap = OldUseMmap;
  }
  
  // 如果需要，分配新内存并复制旧数据
  // ...
}
```

## 3. 内存桶模式的优势

内存桶模式相比传统的内存分配方式有以下优势：

### 3.1 内存效率

内存桶模式通过预分配大块内存并将其划分为多个固定大小的桶，减少了频繁分配和释放小块内存的开销。这种方式可以显著提高内存分配和释放的效率，特别是在需要频繁创建和销毁WebAssembly实例的场景中。

### 3.2 内存保护

内存桶模式使用内存映射（mmap）分配内存，可以利用操作系统的内存保护机制。通过设置内存页的访问权限，可以防止WebAssembly代码访问越界内存，提高系统的安全性。

```cpp
void WasmMemoryAllocator::mprotectReadWriteWasmMemoryData(
    const WasmMemoryData &Data, bool UnprotectBucket) {
  // ...
  if (0 !=
      ::mprotect(Data.MemoryData, Data.MemorySize, PROT_WRITE | PROT_WRITE)) {
    ZEN_ABORT();
  }
}
```

### 3.3 CPU异常检测

内存桶模式支持CPU异常检测，当WebAssembly代码试图访问越界内存时，会触发CPU异常，可以被捕获并处理。这种机制比软件检查更高效，因为它利用了硬件的内存保护功能。

### 3.4 内存复用

内存桶模式支持内存复用，当一个WebAssembly实例被销毁时，其使用的内存桶项可以被其他实例重用。只有当所有桶项都被释放时，才会解除整个内存映射。这种机制减少了内存碎片，提高了内存利用率。

## 4. 内存桶模式的限制

尽管内存桶模式有很多优势，但它也有一些限制：

### 4.1 内存大小限制

内存桶模式对WebAssembly线性内存的大小有限制，如果内存需要增长到超过桶项的容量，就需要重新分配内存，这会导致性能下降。

```cpp
bool InstanceUseMmap =
    OldUseMmap && (NewMemorySize <= MmapMemoryBucketGrowMaxSize);
```

### 4.2 内存浪费

内存桶模式预分配固定大小的桶项，如果WebAssembly实例只使用了很小的内存，会导致内存浪费。

### 4.3 适用性限制

内存桶模式不适用于所有WebAssembly模块，它需要模块满足一定的条件：

```cpp
static bool verifyCanUseMmapBucketByModuleDataSegments(Module *Mod) {
  if (Mod->getNumInternalMemories() != 1) {
    return false;
  }
  const auto &Mem = Mod->getDefaultMemoryEntry();
  size_t InitMemorySize = Mem.InitSize * DefaultBytesNumPerPage;
  if (InitMemorySize == 0) {
    return false;
  }
  if (InitMemorySize > MmapMemoryFileMaxSize) {
    return false;
  }
  // ...
}
```

### 5.3 内存保护

在JIT编译模式下，内存桶模式用于实现内存保护，防止WebAssembly代码访问越界内存：

```cpp
void Instance::protectMemory() {
  if (MemDataKind == WasmMemoryDataType::WM_MEMORY_DATA_TYPE_BUCKET_MMAP ||
      MemDataKind == WasmMemoryDataType::WM_MEMORY_DATA_TYPE_SINGLE_MMAP) {
    WasmMemoryAllocator *Allocator = getWasmMemoryAllocator();
    for (uint32_t I = 0; I < NumTotalMemories; ++I) {
      MemoryInstance &MemInst = Memories[I];
      WasmMemoryData Data = MemInst.getWasmMemoryData();
      Allocator->mprotectReadWriteWasmMemoryData(Data, true);
    }
  }
}
```

## 总结

内存桶模式是DTVM项目中的一种高效内存管理策略，它通过预分配大块内存并将其划分为多个固定大小的桶，来管理WebAssembly线性内存。这种模式提供了内存效率、内存保护、CPU异常检测和内存复用等优势，但也有内存大小限制、内存浪费和适用性限制等缺点。

在DTVM中，内存桶模式主要用于WebAssembly实例创建、内存增长和内存保护等场景，是DTVM内存管理系统的重要组成部分。通过内存桶模式，DTVM能够安全、高效地执行WebAssembly模块，为区块链、边缘计算和安全计算等场景提供可靠的执行环境。
